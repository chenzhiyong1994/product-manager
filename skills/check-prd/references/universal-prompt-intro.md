# B端PRD质量检查 Prompt

> 作者：杨堃，《决胜B端》作者，B端产品专家
> 基于：《决胜B端（第二版）》《决胜体验设计》《决胜B端PRD模板 v2.0》
> 本 Prompt 用于对 B端产品的 PRD 和系统设计方案做全面、系统化的质量检查，覆盖 14 个维度。

## 使用说明

1. 先把待检查的 PRD / 系统设计文档内容完整提供给模型，或上传文档
2. 再发送本 Prompt
3. 模型先完成产品定型，按当前范围覆盖适用维度，再交付一份有证据的报告；只有用户要求逐维度审看时才分段输出

适用场景：

- PRD 评审前自查
- 设计方案质量回顾
- 新人 PRD 写作指导
- 产品方案完整性验证

## 第零步：产品定型

在开始任何维度检查前，先阅读文档并判断以下维度，记录结论供后续检查使用：

**A. 商业属性**

- 自研内部系统：企业内部使用，不对外销售，如内部 OA、ERP、CRM
- 商业化产品：对外销售或运营，存在付费客户或商业变现，如 SaaS、平台产品

**B. 功能类型**

- 业务型管理软件：支撑核心业务流程运转，有复杂业务对象和状态管理
- 工具型软件：提供独立功能提升效率，无复杂业务对象关系
- 交易型平台：撮合多方完成交易
- 基础服务型：提供底层能力供其他系统调用

**C. 文档范围**

- 0-1 完整系统：从无到有建设完整系统或完整产品。
- 系统级重构或大版本：影响系统框架、核心流程、数据模型或多模块协同。
- 模块级迭代：已有系统中的单模块新增、改造或流程优化。
- 单点功能变更：单个按钮、字段、校验、导入导出、展示优化、权限开关、文案或流程小改。
- 快速产品说明：用于沟通或评估的轻量方案说明。

**D. 审查强度**

| 文档范围 | 审查强度 | 审查方式 |
| --- | --- | --- |
| 0-1 完整系统 | 完整严格审查 | 执行 14 个维度，按复杂 B 端系统标准判断完整性 |
| 系统级重构或大版本 | 完整严格审查 | 执行 14 个维度，重点增加迁移、兼容、灰度、历史数据和新旧流程差异 |
| 模块级迭代 | 聚焦审查 | 重点审查场景、结构、局部数据、流程/状态/权限、交互、异常、验收口径；商业、架构、运营按影响范围降低要求 |
| 单点功能变更 | 轻量审查 | 重点审查问题目标、影响范围、入口页面、字段/按钮/规则、状态差异、权限差异、异常兼容、验收标准 |
| 快速产品说明 | 轻量审查 | 只检查目标、范围、关键规则、验收和待决事项是否能支撑沟通与执行 |

降低标准原则：

- 对模块级迭代、单点功能变更、快速产品说明，不得因为缺少完整 14 章、完整商业分析、完整系统架构图、完整 ER 图、完整运营计划而直接判定为“严重缺失”。
- 降低标准不等于放松关键实现信息。凡是影响研发、测试、权限、数据、状态、兼容和上线风险的信息，仍应严格检查。
- 涉及有状态实体时，无论文档范围大小，都要检查不同状态下字段和操作的可见、可编辑、可触发规则。

**根据定型结论，以下维度按条件适用：**

| 维度 | 适用条件 | 不适用时处理方式 |
| --- | --- | --- |
| 07-数据建模（ER图） | 仅适用于业务型管理软件和交易型平台 | 工具型或基础服务型标注“不适用”，仅检查关键数据结构 |
| 10-商业分析 | 仅适用于商业化产品 | 自研内部系统仅执行投入产出分析 |
| 03 维度中的竞品分析 | 仅适用于商业化产品 | 自研内部系统改为同类系统参考 |
| 06-企业架构层 6.5-6.9 | 仅适用于 0-1 新系统设计或系统级规划 PRD | 迭代需求或模块级需求只做 6.1-6.4 |
| R8-多租户风险项 | 仅适用于商业化 SaaS 产品 | 非 SaaS 标注“不适用” |
| 13-AI 功能 | 仅在文档涉及 AI 功能时评估 | 否则标注“不适用” |
| 完整14章结构 | 仅适用于 0-1 完整系统、系统级重构或大版本 | 模块级/单点需求按其分支结构检查 |
| 完整ER图 | 仅适用于核心数据模型变化、0-1完整系统、交易闭环变化 | 轻量需求只检查受影响字段和局部数据关系 |
| 完整运营计划 | 仅适用于商业化产品上线、重大系统推广、流程变更影响大量用户 | 单点功能只检查发布说明、培训或通知是否必要 |

## 检查输出规范

**核心原则：按范围完成审查，以证据决定发现。**

默认集中交付完整报告，同一问题跨维度出现时合并说明影响。用户只要报告时不改原文；明确要求完善文档时，完成审查后继续已授权修订，不停在建议。

**每个维度使用以下格式：**

```md
## 维度[编号] - [名称] ｜ 评级：[优秀 / 合格 / 待改进 / 严重缺失]

### 具体发现

**发现 1：[问题标题]** [P0/P1/P2/P3]
- PRD定位：第X节/[功能名称]
- 问题描述：[具体说明问题，不要泛泛而谈]
- 改进示例：[给出可立刻执行的改法]

### 隐性问题推断
结合产品类型和业务场景，列出 PRD 没写但按道理必须考虑的问题。
```

**最低输出要求：**

- 完整严格审查：覆盖每个适用维度；发现数量由证据决定，没有问题时简述已检查边界
- 聚焦审查：报告重点维度中的真实问题和必要边界说明，不凑固定数量
- 轻量审查：围绕影响范围、字段规则、状态权限、异常兼容、验收标准输出核心发现，不强制每个维度凑满 3 条
- 每条发现必须引用 PRD 中的具体章节、流程、功能名或界面名
- 每条发现必须给出具体可执行的改进示例
- 维度 09 必须逐个检查文档中出现的界面、弹窗、表单、操作，并指出缺失的交互说明
- 有状态实体时，必须检查是否说明“状态 × 字段/操作 × 角色”的可见、可编辑、可触发规则
